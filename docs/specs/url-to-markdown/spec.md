# URL을 Markdown으로 변환해 LLM으로 넘기기

연결된 출처:

- `docs/decisions/ui-composition.md`: 화면의 component, token, 상태 표현, 반응형 배치는 이 결정을 따릅니다.
- `docs/decisions/dependency-versions.md`: 새로 들이는 의존성(`defuddle`, DOM 구현체 등)의 버전 범위는 이 결정을 따릅니다.
- `docs/specs/url-to-markdown/prototype.html`: 승인된 화면입니다. 화면 구성, 상태별 모습(첫 화면, 변환 중, 결과, 오류, 긴 본문 안내), 반응형 배치, 문구는 이 프로토타입을 따릅니다. 더미 데이터와 리뷰용 상단 막대는 제품에 넣지 않습니다.

## 사용자가 얻는 결과

웹 페이지 주소 하나를 붙여넣으면, 광고와 메뉴를 걷어낸 본문만 Markdown으로 받아 볼 수 있습니다. 결과는 복사하거나 `.md` 파일로 내려받을 수 있고, 원하는 지시문을 앞에 붙여 ChatGPT나 Claude 채팅으로 바로 넘길 수 있습니다.

## 범위

한 화면에서 아래 흐름이 모두 동작합니다.

1. **입력**: URL 입력창, 변환 버튼, 입력과 결과를 초기화하는 지우기 버튼.
2. **변환**: 입력한 페이지의 본문을 `defuddle`로 추출해 Markdown으로 만듭니다.
3. **결과 확인**: 페이지 제목과 저자를 머리글로 보여 주고, 그 아래에 Markdown을 렌더링해 보여 줍니다.
4. **내보내기**
   - 복사하기, `.md` 파일 다운로드.
   - ChatGPT로 열기, Claude로 열기. 선택한 프롬프트가 있으면 본문 앞에 붙입니다.
5. **프롬프트 선택**: 없음(기본) / 요약해줘 / 한국어로 번역해줘 / 쉽게 설명해줘 / 직접 입력. "직접 입력"을 고르면 텍스트 입력창이 나타나고, 입력한 문구는 저장하지 않습니다.
6. **다크모드 토글**.

## 수용 기준

- `https://stephango.com/saw`를 변환하면 머리글에 제목 "Use the saw, fear the saw"와 저자 "Steph Ango"가 보이고, 본문이 렌더링된 Markdown으로 보입니다.
- 저자가 없는 페이지(예: `https://example.com/`)는 저자 자리를 비우거나 숨기고, 빈 라벨이나 "undefined"를 보여 주지 않습니다.
- 지우기 버튼을 누르면 입력창, 결과, 오류 메시지가 모두 처음 상태로 돌아갑니다.
- 변환 중에는 진행 상태가 보이고, 변환 버튼을 다시 누를 수 없습니다.
- URL 형식이 아니거나, 페이지를 가져오지 못하거나, 본문을 추출하지 못하면 결과 자리에 이유를 알 수 있는 오류 메시지가 보이고 화면은 계속 쓸 수 있습니다.
- 복사하기를 누르면 내보낼 Markdown이 클립보드에 들어가고, 복사됐다는 피드백이 보입니다.
- 다운로드를 누르면 내보낼 Markdown이 `.md` 파일로 저장됩니다.
- 프롬프트를 고르지 않고 ChatGPT·Claude로 열면 Markdown만 넘어가고, 프롬프트를 고르면 프롬프트 다음 줄부터 Markdown이 이어진 텍스트가 넘어갑니다.
- 넘길 텍스트가 길이 기준 이하이면 새 탭에서 해당 서비스의 새 채팅이 열리고 입력창에 그 텍스트가 채워져 있습니다.
- 넘길 텍스트가 길이 기준을 넘으면 전체 텍스트를 클립보드에 복사하고, 프롬프트만 채운 새 채팅을 연 뒤, 붙여넣기 하라는 안내를 화면에 보여 줍니다. `https://en.wikipedia.org/wiki/Markdown`(Markdown 약 34,000자)으로 이 경로를 확인합니다.
- "직접 입력"을 고르면 텍스트 입력창이 나타나고, 거기 쓴 문구가 프리셋 대신 앞에 붙습니다. 새로고침하면 입력한 문구는 남아 있지 않습니다.
- 다크모드 토글을 누르면 화면 전체가 라이트·다크 사이에서 바뀝니다.
- 넓은 화면에서는 결과가 왼쪽 본문과 오른쪽 내보내기 패널로 나뉘고, 긴 본문을 아래로 스크롤해도 내보내기 패널이 화면에 계속 보입니다.
- 좁은 화면에서는 내보내기 패널이 본문 위로 쌓이고, 화면이 옆으로 넘치지 않으며 입력, 결과, 내보내기 동작을 모두 쓸 수 있습니다.

## 확정된 제약과 이유

- **본문 추출은 `defuddle` 라이브러리로 합니다.** 사용자가 지정한 필수 조건입니다. defuddle.md의 호스팅 API는 쓰지 않습니다. 요청 수가 제한되고, 늘리려면 유료 키가 필요합니다.
- **페이지를 가져와 변환하는 일은 서버에서 합니다.** 브라우저에서 다른 사이트의 HTML을 직접 가져오면 CORS에 막힙니다. 2026-11-18에 이 프로젝트의 복사본(Next.js 16.4.5, Node 26)에서 서버 쪽 `defuddle/node` + `linkedom` 조합으로 세 페이지를 변환해 제목, 저자, Markdown이 정상으로 나오는 것을 확인했습니다.
- **긴 본문은 주소에 담지 않고 클립보드로 넘깁니다.** 채팅 서비스는 주소로 입력창을 채우는데, 긴 본문은 주소 길이 제한을 넘어 열리지 않습니다. 사용자가 "짧으면 입력창 채움, 길면 복사 후 안내" 방식을 골랐습니다. 본문을 잘라서 넘기는 방식은 내용이 빠져서 택하지 않았습니다.
- **직접 입력한 프롬프트는 저장하지 않습니다.** 사용자가 1회용으로 정했습니다.
- **내보내기 동작은 본문 옆 패널에 둡니다.** 사용자가 세 배치(본문 위 패널, 하단 고정 바, 오른쪽 사이드 패널)를 비교한 뒤 오른쪽 사이드 패널을 골랐습니다. 긴 본문을 읽는 도중에도 복사, 프롬프트 선택, LLM으로 열기에 바로 손이 닿습니다.

## 가정 (구현 중 바꿀 수 있음)

- 채팅을 여는 주소는 ChatGPT `https://chatgpt.com/?q=<텍스트>`, Claude `https://claude.ai/new?q=<텍스트>`입니다.
- 길이 기준은 인코딩한 텍스트 기준 약 8,000자입니다. 실제로 열어 보고 더 짧아야 하면 낮춥니다.
- 복사·다운로드·LLM으로 넘기는 Markdown은 맨 앞에 `# 제목`과 원문 URL을 붙입니다. defuddle이 본문에서 제목과 같은 첫 제목을 지우기 때문에, 붙이지 않으면 LLM이 출처를 모릅니다.
- 프롬프트는 ChatGPT·Claude로 열 때만 붙이고, 복사와 다운로드에는 붙이지 않습니다.
- `.md` 파일 이름은 페이지 제목을 파일명으로 쓸 수 있게 바꾼 것이고, 제목이 없으면 도메인을 씁니다.
- 다크모드는 처음에는 시스템 설정을 따르고, 토글로 고른 값은 브라우저에 기억합니다.
- 결과 영역은 렌더링된 Markdown만 보여 주고, 원문 Markdown 보기 탭은 두지 않습니다.
- 사용자가 `https://`를 빼고 입력하면 `https://`를 붙여 처리합니다.

## 범위 밖

- 로그인, 변환 기록 저장, 즐겨찾기: 1회성 변환 도구로 충분합니다.
- 직접 입력한 프롬프트나 프리셋 목록 저장·편집: 사용자가 1회용으로 정했습니다.
- 로그인이 필요한 페이지, 자바스크립트로만 본문을 그리는 페이지의 추출 보장: 서버가 받은 HTML만 변환합니다.
- 서버 요청 남용 방지, 대상 주소 제한 같은 보안 하드닝: 강의용 템플릿의 검증 예산(`AGENTS.md`) 밖입니다.

## 남은 위험

- ChatGPT·Claude의 `?q=` 입력창 채우기는 공식 문서가 없는 동작이라, 서비스가 바꾸면 입력창이 비어 열릴 수 있습니다. 그때도 길이 기준을 넘는 경우처럼 클립보드 복사 경로로 넘길 수 있습니다.
- 한국어 글은 대부분 입력창을 바로 채우지 못하고 클립보드 경로로 넘어갑니다. 주소에서 한글 한 글자가 9자로 늘어나서, 약 900자만 넘어도 길이 기준을 넘기 때문입니다(프로토타입에서 519자 글이 3,194자가 됐습니다). 동작은 수용 기준대로이지만, 한국어 사용자에게는 붙여넣기가 기본 경험이 됩니다.
- 사이트에 따라 봇 요청을 막거나, 본문 대신 메뉴만 추출될 수 있습니다.
- 스펙을 검증하던 복사본에서 `bun run build`의 타입 검사 단계가 한 번 네이티브 오류로 죽었습니다. 같은 코드에서 `tsc --noEmit`은 통과했으므로 defuddle 문제로 보이지 않지만, 구현 중 빌드가 다시 죽으면 따로 살펴봅니다.
