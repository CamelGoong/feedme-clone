# 변환한 글 저장하고 내 글만 보기

연결된 출처:

- `docs/decisions/ui-composition.md`: 새 화면(저장한 글 목록, 저장한 글 보기)의 component, token, 빈 상태·오류 상태, 반응형 배치는 이 결정을 따릅니다.
- `docs/decisions/dependency-versions.md`: 새 의존성을 들일 때의 버전 범위는 이 결정을 따릅니다.
- 승인된 프로토타입은 없습니다. 새 화면은 기존 변환 화면(`docs/specs/url-to-markdown/`)과 같은 시각 언어를 따릅니다.

## 사용자가 얻는 결과

로그인한 사용자는 변환한 글을 한 번에 저장해 두고, 나중에 "저장한 글" 목록에서 다시 열어 볼 수 있습니다. 목록에는 본인이 저장한 글만 나옵니다. 다른 계정이 저장한 글은 보이지도, 열리지도 않습니다.

## 범위

1. **저장**: 변환 결과 화면에서 로그인한 사용자가 저장 버튼으로 현재 글을 저장합니다. 저장하는 것은 변환 결과 전체(제목, 저자, 사이트, 발행일, 원문 URL, Markdown 본문)입니다.
2. **저장한 글 목록**: 본인이 저장한 글을 최근 저장한 순서로 보여 줍니다. 각 항목에는 제목, 저자(있을 때), 원문 도메인, 저장한 날짜가 보입니다.
3. **저장한 글 보기**: 목록에서 글을 고르면 저장해 둔 내용으로 변환 결과와 같은 모습(머리글과 렌더링된 Markdown, 내보내기 패널)을 보여 줍니다. 원문 페이지를 다시 가져오지 않습니다.
4. **본인 글만 접근**: 글은 저장한 사용자에게만 읽히고 쓰입니다. 이 제한은 화면 코드가 아니라 데이터베이스 수준에서 강제합니다.
5. **진입 경로**: 로그인한 상태의 첫 화면 머리글에 "저장한 글" 링크가 있습니다.

## 수용 기준

- 로그인한 사용자가 글을 변환하면 결과 화면에 저장 버튼이 보이고, 누르면 저장됐다는 피드백이 보입니다.
- 저장한 글은 "저장한 글" 목록에 제목, 도메인, 저장 날짜와 함께 나타납니다. 저자가 없는 글은 저자 자리를 비우거나 숨기고, 빈 라벨이나 "undefined"를 보여 주지 않습니다.
- 목록에서 글을 열면 저장해 둔 제목, 저자, Markdown 본문이 그대로 보이고, 복사·다운로드·LLM으로 열기가 변환 직후와 같이 동작합니다.
- 같은 사용자가 같은 URL을 다시 저장하면 목록에 항목이 하나만 있고, 내용은 방금 변환한 것으로 갱신됩니다.
- 로그인하지 않은 사용자는 저장 버튼 자리에 로그인 안내가 보이고, 누르면 로그인 화면으로 이동합니다. `/articles` 주소로 직접 들어가면 로그인 화면으로 보냅니다. 변환과 내보내기는 로그인 없이 지금처럼 동작합니다.
- 저장한 글이 없으면 목록 자리에 빈 상태 안내가 보입니다.
- 저장에 실패하면(네트워크 오류 등) 이유를 알 수 있는 오류 메시지가 보이고, 화면은 계속 쓸 수 있습니다.
- **두 계정 확인**: `test1`로 글 하나를 저장하면 `test1`의 목록에 보입니다. `test2`로 로그인하면 목록이 비어 있습니다. `test2`가 다른 글을 저장한 뒤 `test1`로 다시 로그인하면 `test1`이 저장한 글만 보입니다.
- `test2`가 `test1` 글의 상세 주소로 직접 들어가면 글 내용이 아니라 "찾을 수 없음" 상태가 보입니다.
- 좁은 화면에서도 목록과 저장한 글 보기가 옆으로 넘치지 않고 모든 동작을 쓸 수 있습니다.

## 확정된 제약과 이유

- **변환 결과 전체를 저장합니다.** 사용자가 골랐습니다. 목록에서 다시 열 때 서버 변환을 기다리지 않고, 원문이 바뀌거나 사라져도 저장한 시점의 글이 남습니다. 대신 글마다 본문 크기만큼 데이터가 쌓입니다.
- **접근 제한은 글 테이블의 RLS로 합니다.** 글은 저장한 사용자에게만 읽히고 쓰입니다. 기존 `profiles` 테이블과 같은 방식(익명 접근 없음, 로그인 사용자는 자기 행만)을 따릅니다. 화면에서 `where user_id = ...`로 거르는 것만으로는 이 기준을 채우지 않습니다.
- **기존 변환 흐름은 로그인 없이 그대로 동작합니다.** 저장만 로그인이 필요합니다.

## 가정 (구현 중 바꿀 수 있음)

- 목록 주소는 `/articles`, 저장한 글 보기는 `/articles/<id>`입니다.
- 같은 사용자의 같은 URL(정규화한 값)은 한 항목으로 취급해 다시 저장하면 덮어씁니다. 저장 버튼은 이미 저장된 글에서는 "저장됨"으로 보입니다.
- 목록은 최근 저장순이고, 페이지 나누기와 검색은 없습니다.
- 로그인 화면으로 갔다 오면 변환 결과는 사라지고 첫 화면으로 돌아옵니다. 로그인 후 자동 저장은 하지 않습니다.
- 저장한 글을 삭제하는 기능은 이번 범위에 넣지 않습니다. 필요하면 다음 스펙으로 다룹니다.

## 범위 밖

- 저장한 글 삭제·수정, 폴더·태그, 검색, 페이지 나누기: 저장과 본인 글만 보기를 먼저 증명하는 것이 목적입니다.
- 글 공유나 다른 사용자에게 공개: 이 기능은 본인 전용입니다.
- 저장한 글의 원문 갱신 추적: 저장 시점의 내용만 보관합니다.
- 서버 요청 남용 방지, 저장 용량 제한 같은 보안 하드닝: 강의용 템플릿의 검증 예산(`AGENTS.md`) 밖입니다.

## 남은 위험

- 글 하나가 수십 KB이고 변환 결과 길이에 제한을 두지 않으므로, 아주 긴 글은 저장이 느리거나 실패할 수 있습니다. 실패하면 위 오류 상태로 보입니다.
- 승인된 프로토타입 없이 구현하므로, 목록과 저장한 글 보기의 정확한 모습은 구현 뒤 화면을 보고 다듬어야 할 수 있습니다.
