# URL to Markdown 변환과 LLM 전달 방식

## Decisions

- 본문 추출은 `defuddle` 라이브러리로 하고, 페이지를 가져와 변환하는 일은 서버(`defuddle/node` + `linkedom`)에서 합니다.
- defuddle.md의 호스팅 API는 쓰지 않습니다.
- ChatGPT·Claude로 넘길 텍스트가 길이 기준(`CHAT_TEXT_LIMIT`)을 넘으면 주소에 담지 않습니다. 전체 텍스트를 클립보드에 복사하고, 프롬프트만 채운 새 채팅을 연 뒤 붙여넣기 안내를 보여 줍니다.
- 직접 입력한 프롬프트는 저장하지 않습니다.
- 내보내기 동작(복사, 다운로드, 프롬프트 선택, LLM으로 열기)은 넓은 화면에서 본문 옆 오른쪽 패널에 두고, 본문을 스크롤해도 계속 보이게 합니다.

## Why

- 브라우저에서 다른 사이트의 HTML을 직접 가져오면 CORS에 막힙니다.
- 호스팅 API는 요청 수가 제한되고, 늘리려면 유료 키가 필요합니다. `defuddle` 라이브러리 사용은 사용자가 지정한 필수 조건입니다.
- 채팅 서비스는 `?q=` 주소로 입력창을 채우는데, 긴 본문은 주소 길이 제한을 넘어 열리지 않습니다.
- 내보내기 패널을 본문 옆에 두면 긴 본문을 읽는 도중에도 복사와 LLM 전달에 바로 손이 닿습니다.

## Boundaries

- 서버가 받은 HTML만 변환합니다. 로그인이 필요한 페이지와 자바스크립트로만 본문을 그리는 페이지의 추출은 보장하지 않습니다.
- 한글은 주소에서 한 글자가 9자로 늘어나므로, 한국어 글은 약 900자만 넘어도 길이 기준을 넘어 클립보드 경로로 갑니다.

## Reconsider when

- ChatGPT·Claude의 `?q=` 입력창 채우기가 공식 문서 없는 동작이므로, 서비스가 바꿔 입력창이 비어 열리면 클립보드 경로를 기본으로 삼을지 다시 봅니다.

## Still-rejected alternatives

- 긴 본문을 잘라서 주소로 넘기는 방식: 내용이 빠집니다.
- 브라우저에서 직접 페이지를 가져오는 방식: CORS로 막힙니다.
- 내보내기 동작을 본문 위 패널이나 하단 고정 바에 두는 방식: 세 배치를 비교한 뒤 오른쪽 사이드 패널을 골랐습니다.
